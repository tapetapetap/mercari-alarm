# Feature Specification: 메르카리 키워드 신착 알림기 (1단계)

**Feature Branch**: `001-keyword-alarm`

**Created**: 2026-09-26

**Status**: Draft

**Input**: User description: "intent.md의 1단계: 나만 쓰는 메르카리(일본) 신착 1분 알림기. 윈도우 PC에서 상시 실행되며 키워드별로 판매 중 신상품을 1분마다 조회, 새 상품을 ntfy 푸시로 알리고(누르면 jp.mercari.com/item/<ID> 열림), 폰 홈 화면 웹 UI(PWA, Tailscale 경유)에서 키워드를 보고/추가/삭제한다. 신규 키워드 첫 조회는 무알림, 키워드당 5건 초과 시 묶음, 10분 연속 실패 시 경고 푸시. 한국어로 작성. 범위와 제외 항목은 intent.md를 따른다."

> 범위의 기준은 루트 `intent.md`(1단계)다. 이 명세는 intent의 "하지 않는 것"을 포함하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 새 상품 푸시 알림 받기 (Priority: P1)

사용자는 관심 있는 키워드(예: `ポケモンカード 151`)를 등록해 둔다. 일본 메르카리에 그 키워드로 검색되는
**판매 중** 상품이 새로 올라오면, 사용자의 폰(iPhone·Android)에 1~2분 안에 푸시 알림이 온다.
알림에는 키워드, 상품명, 가격(엔)이 보이고, 알림을 누르면 그 상품 페이지가 열린다.

**Why this priority**: 이 앱이 존재하는 이유 그 자체다. 이것만 동작해도 키워드를 파일로 넣어 두고 쓸 수 있다.

**Independent Test**: 키워드 하나를 등록한 상태로 알림기를 켜 두고, 그 키워드로 새 상품이 올라올 때
(또는 테스트용으로 흔한 키워드를 써서) 폰에 알림이 오고, 누르면 해당 상품 페이지가 열리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 키워드 A가 등록되어 있고 이미 한 번 이상 조회됨, **When** 키워드 A에 맞는 판매 중 상품이 새로 올라옴,
   **Then** 2분 안에 제목=키워드 A, 본문=상품명과 가격(¥)인 푸시가 온다.
2. **Given** 1번의 알림이 도착함, **When** 사용자가 알림을 누름,
   **Then** 그 상품의 메르카리 상품 페이지(`https://jp.mercari.com/item/<상품ID>`)가 열린다.
3. **Given** 어떤 상품으로 이미 알림을 보냄, **When** 이후 조회에서 같은 상품이 다시 검색됨,
   **Then** 다시 알리지 않는다 (알림기를 재시작한 뒤에도 마찬가지).
4. **Given** 키워드 A를 방금 새로 등록함, **When** 키워드 A의 첫 조회가 이루어짐,
   **Then** 그때 이미 올라와 있던 상품은 알리지 않고 "이미 본 상품"으로만 기록한다.
5. **Given** 한 번의 조회에서 키워드 A의 새 상품이 8개 발견됨, **When** 알림을 보냄,
   **Then** 가장 최근 5개는 개별 알림으로, 나머지 3개는 "외 3건" 알림 하나로 보낸다.

---

### User Story 2 - 폰에서 키워드 보기·추가·삭제 (Priority: P2)

사용자는 폰 홈 화면의 아이콘을 눌러 관리 화면을 연다. 화면에는 등록된 키워드 목록이 있고,
새 키워드를 입력해 추가하거나 기존 키워드를 삭제할 수 있다. 집 밖(모바일 데이터)에서도 된다.
바뀐 키워드는 다음 조회 주기부터 반영된다.

**Why this priority**: PC 앞에 가지 않고 키워드를 바꿀 수 있어야 실제로 계속 쓰게 된다.
다만 P1 없이는 의미가 없고, P1은 이것 없이도 동작한다.

**Independent Test**: 폰에서 관리 화면을 열어 키워드를 추가하고, 목록에 나타나는지, 1~2분 뒤
그 키워드가 조회 대상이 되는지(첫 조회는 무알림) 확인한다. 삭제 후에는 그 키워드로 알림이 오지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 폰이 PC와 같은 사설망에 연결됨, **When** 홈 화면 아이콘으로 관리 화면을 엶,
   **Then** 등록된 키워드 목록이 보인다.
2. **Given** 관리 화면이 열림, **When** 새 키워드를 입력하고 추가함,
   **Then** 목록에 즉시 나타나고, 다음 조회 주기부터 조회된다 (첫 조회는 무알림).
3. **Given** 키워드 A가 등록됨, **When** 키워드 A를 삭제함,
   **Then** 목록에서 즉시 사라지고, 이후 키워드 A로는 알림이 오지 않는다.
4. **Given** 이미 등록된 키워드와 같은 키워드(앞뒤 공백 무시)를 추가함, **Then** 중복으로 추가되지 않고 그 사실을 보여준다.
5. **Given** 빈 키워드 또는 50자를 넘는 키워드를 추가하려 함, **Then** 추가되지 않고 이유를 보여준다.
6. **Given** 폰이 사설망에 연결되지 않은 상태(인터넷에서 직접), **When** 관리 화면 주소로 접속 시도,
   **Then** 접속되지 않는다.

---

### User Story 3 - 알림기 고장 알아차리기 (Priority: P3)

메르카리 조회가 계속 실패하면(네트워크 끊김, 메르카리 차단, 메르카리 변경 등) 사용자에게
"알림기 조회 실패 중" 푸시가 한 번 온다. 복구되면 다시 조용해지고, 다음에 또 고장 나면 다시 알린다.

**Why this priority**: "알림이 안 오면 새 상품이 없는 것"이라고 믿을 수 있어야 한다. 조용히 죽는 것을 막는다.

**Independent Test**: 알림기가 조회하는 동안 PC의 네트워크를 10분 이상 끊었다가 다시 연결해,
재연결 직후 경고 푸시가 한 번만 오는지 확인한다. (네트워크가 끊긴 동안에는 푸시를 보낼 수 없으므로,
실패가 연속 10분을 넘긴 뒤 처음으로 푸시를 보낼 수 있을 때 보낸다.)

**Acceptance Scenarios**:

1. **Given** 조회가 정상이다가, **When** 모든 조회가 10분 이상 연속 실패함,
   **Then** "알림기 조회 실패 중" 푸시를 한 번 보낸다 (그 뒤로 실패가 계속돼도 반복하지 않음).
2. **Given** 1번의 경고를 보낸 상태, **When** 조회가 다시 성공함, **Then** 경고 상태를 초기화한다.
3. **Given** 2번 이후, **When** 다시 10분 이상 연속 실패함, **Then** 경고 푸시를 다시 한 번 보낸다.
4. **Given** 키워드 하나의 조회만 실패하고 다른 키워드는 성공함, **Then** 다른 키워드의 조회와 알림은 계속된다.

---

### Edge Cases

- **알림기(PC)가 꺼져 있던 동안 올라온 상품**: 다시 켜지면 첫 조회에서 이미 본 상품이 아닌 것들을 알린다.
  최신 120개 범위 안에서만 잡히며, 많으면 5건+"외 N건" 규칙으로 묶인다.
- **키워드를 삭제했다가 다시 추가**: 새 키워드로 취급한다 (첫 조회 무알림).
- **같은 상품이 두 키워드에 모두 걸림**: 키워드마다 한 번씩 알린다 (키워드별로 기억).
- **가격이 바뀌거나 재등록되지 않은 같은 상품**: 같은 상품 ID면 다시 알리지 않는다. 키워드 등록 전부터 있던 상품이
  가격 수정으로 목록 위로 올라와도 알리지 않는다 (가격 인하 알림은 범위 밖).
- **아주 넓은 키워드**(예: `ポケモンカード`): 1분 사이 갱신이 120건을 넘으면 새 상품을 놓칠 수 있다. 구체적인 키워드를 권장한다.
- **메르카리 Shops 상품**: 일반 상품과 같이 알리며, 누르면 Shops 상품 페이지가 열린다.
- **판매 완료·거래 중 상품**: 조회 대상이 아니다.
- **키워드가 0개**: 조회하지 않고 대기한다. 관리 화면은 정상 동작한다.
- **키워드 개수 상한**: 최대 20개. 넘으면 추가를 거절하고 이유를 보여준다.
- **푸시 전송 자체가 실패**: 기록을 남기고, 그 상품은 "이미 본 상품"으로 처리하지 않아 다음 주기에 다시 시도한다.
- **기억 데이터가 무한히 쌓임**: 키워드별로 최근 일정 개수만 기억하며, 조회 범위(최신 120개)보다 넉넉히 유지해
  오래된 상품이 다시 알려지지 않게 한다. 삭제된 키워드의 기억은 지운다.
- **PC 자체가 꺼짐**: 경고할 수 없다 (intent에서 감수).

## Requirements *(mandatory)*

### Functional Requirements

**조회·알림 (US1)**

- **FR-001**: 시스템은 등록된 키워드마다 약 1분 주기로 일본 메르카리에서 그 키워드의 **판매 중** 상품을
  **신상품순**으로 최신 120개까지 조회해야 한다(MUST). (메르카리의 신상품순은 가격 수정 등으로 갱신된 기존 상품도 위로 올린다.)
- **FR-002**: 시스템은 키워드 사이에 몇 초 간격을 두고 차례로 조회해야 한다(MUST). 동시에 여러 요청을 보내지 않는다.
- **FR-003**: 시스템은 키워드별로 이미 본 상품 ID를 기억하고, 기억에 없으면서 **키워드 등록(첫 조회) 이후에 등록된** 상품만
  "새 상품"으로 판단해야 한다(MUST). 등록 시각이 그 이전인 상품(가격 수정 등으로 위로 올라온 기존 상품)은 알리지 않고 기억에만 추가한다.
- **FR-004**: 시스템은 새로 등록된 키워드의 첫 조회 결과를 알리지 않고 기억에만 추가해야 한다(MUST).
- **FR-005**: 시스템은 새 상품마다 푸시를 보내야 한다: 제목=키워드, 본문=상품명과 가격(¥),
  누르면 `https://jp.mercari.com/item/<상품ID>`가 열림 (메르카리 Shops 상품은 `https://jp.mercari.com/shops/product/<상품ID>`)(MUST).
- **FR-006**: 한 조회에서 한 키워드의 새 상품이 5개를 넘으면, 최신 5개만 개별 푸시로 보내고
  나머지는 개수를 적은 "외 N건" 푸시 하나로 보내야 한다(MUST). "외 N건" 푸시를 누르면 그 키워드의 메르카리 검색 결과가 열린다.
- **FR-007**: 기억은 알림기 재시작 후에도 유지되어야 한다(MUST).
- **FR-008**: 푸시 전송이 실패한 상품은 기억에 추가하지 않아 다음 주기에 다시 시도해야 한다(MUST).

**키워드 관리 (US2)**

- **FR-009**: 사용자는 폰 홈 화면에 추가할 수 있는 관리 화면에서 키워드 목록을 볼 수 있어야 한다(MUST).
- **FR-010**: 사용자는 관리 화면에서 키워드를 추가·삭제할 수 있어야 하며, 결과는 즉시 목록에 반영되고
  다음 조회 주기부터 조회에 반영되어야 한다(MUST). 알림기 재시작은 필요 없다.
- **FR-011**: 키워드는 앞뒤 공백을 제거한 뒤 1~50자여야 하고, 이미 등록된 것과 정확히 같은 문자열은 중복으로 거절하며
  (대소문자·전각/반각이 다르면 다른 키워드로 본다), 최대 20개까지 등록할 수 있어야 한다(MUST). 거절 시 이유를 보여준다.
- **FR-012**: 관리 화면은 사용자의 사설망(PC와 폰을 잇는 개인 사설망, 집 LAN)에서만 접근 가능해야 하고,
  인터넷에서 직접 접근되면 안 된다(MUST NOT).
- **FR-013**: 관리 화면은 입력된 키워드를 화면에 표시할 때 그대로 해석하지 않고 글자로만 표시해야 한다(MUST).
- **FR-014**: 키워드 목록은 사용자가 PC에서 텍스트 편집기로도 고칠 수 있는 형태로 저장되어야 한다(MUST).
- **FR-015**: 키워드가 삭제되면 그 키워드의 기억도 지워야 한다(MUST).

**고장 감지 (US3)**

- **FR-016**: 모든 조회·알림 실패는 원인과 시각을 로그 파일에 남겨야 한다(MUST).
- **FR-017**: 조회가 10분 이상 연속 실패하면(그 사이 성공한 키워드 조회가 하나도 없음) "알림기 조회 실패 중" 푸시를
  한 번 보내야 하고, 푸시를 보낼 수 없는 상태면 보낼 수 있게 된 첫 시점에 보내야 한다(MUST).
- **FR-018**: 경고를 보낸 뒤 조회가 한 번이라도 성공하면 경고 상태를 초기화해야 한다(MUST).
- **FR-019**: 한 키워드의 조회 실패가 다른 키워드의 조회·알림이나 관리 화면을 멈추게 하면 안 된다(MUST NOT).

**운영**

- **FR-020**: 알림기는 PC가 켜지면(재부팅 포함) 사용자가 로그인하지 않아도 자동으로 시작되어야 하고,
  비정상 종료되면 자동으로 다시 시작되어야 한다(MUST).
- **FR-021**: 알림기는 실행 중 화면에 창을 띄우지 않아야 한다(MUST).
- **FR-022**: 푸시 채널 식별자 등 비밀 값은 저장소에 커밋되지 않는 설정 파일에서 읽어야 한다(MUST).

### Key Entities

- **키워드**: 사용자가 등록한 검색어. 속성: 검색 문자열(1~50자). 최대 20개.
- **본 상품 기억**: 키워드별로 이미 본(알렸거나 첫 조회로 기록한) 상품 ID 모음과 키워드 첫 조회 시각. 키워드 삭제 시 함께 삭제.
- **상품**: 조회 결과 한 건. 속성: 상품 ID, 상품명, 가격(엔), 등록 시각, 종류(일반/Shops). 상품 페이지 주소는 ID와 종류로 만든다.
- **알림**: 사용자 폰으로 가는 푸시. 종류: 새 상품 / "외 N건" 묶음 / 조회 실패 경고.
- **고장 감지 상태**: 마지막 조회 성공 시각, 경고 발송 여부.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 등록된 키워드의 새 상품 중 90% 이상이, 메르카리 검색에 나타난 뒤 **2분 안에** 폰에 알림으로 도착한다.
- **SC-002**: 1주일 사용 동안 **같은 상품으로 두 번 알림이 오는 일이 0건**이다 (같은 키워드 기준).
- **SC-003**: 폰에서 관리 화면을 열어 키워드 하나를 추가하는 데 **30초 이내**가 걸린다.
- **SC-004**: 새로 추가한 키워드 때문에 **기존 상품 알림이 쏟아지는 일이 0건**이다.
- **SC-005**: 조회가 10분 넘게 막히면 사용자가 **푸시로 알게 되는 비율 100%** (PC와 네트워크가 켜져 있는 경우).
- **SC-006**: PC를 재부팅한 뒤 사용자가 아무것도 하지 않아도 **5분 안에** 알림기가 다시 동작한다.
- **SC-007**: 알림기가 도는 동안 PC 게임 체감 성능 저하가 없다 (사용자 판단).
- **SC-008**: 추가 월 비용 0원 (PC 전기료 제외).

## Assumptions

- 사용자는 1명(본인)이다. 로그인·사용자 구분은 없다 (intent 1단계).
- 알림기는 집 Windows PC에서 24시간 실행되며, PC와 폰에 개인 사설망 도구(intent: Tailscale)와
  푸시 수신 앱(intent: ntfy)이 설치되어 있다.
- 메르카리 조회는 공식 API가 없어 웹이 쓰는 비공식 경로를 쓴다. 메르카리가 바꾸면 조회 부분만 고친다 (constitution III).
- 알림을 눌렀을 때 메르카리 앱이 있으면 앱으로, 없으면 기본 브라우저로 열린다. 특정 브라우저를 강제하지 않는다.
- "2분 안" 기준은 메르카리 검색 결과에 상품이 반영된 시점부터다. 메르카리 자체의 검색 반영 지연은 통제할 수 없다.
- 집 와이파이에 접속한 다른 사람은 관리 화면을 열 수 있다 (intent에서 감수).
- 가격·제외어·상태·카테고리 필터, 알림 기록 화면, 자체 앱, 미국 메르카리는 범위 밖이다 (intent "하지 않는 것").
