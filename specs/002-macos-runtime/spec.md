# Feature Specification: 알림기 실행 위치를 맥북으로 이전

**Feature Branch**: `002-macos-runtime`

**Created**: 2026-10-04

**Status**: Draft

**Input**: User description: "알림기 실행 위치를 Windows PC에서 사용자의 맥북(들고 다님)으로 옮긴다. launchd 에이전트로 로그인 시 자동 시작·재시작, caffeinate -i로 덮개가 열린 동안 저절로 잠들지 않게 함. 잠자기에서 깨어날 때 잘못된 '조회 실패 중' 경고를 보내지 않음(주기 간격이 비정상적으로 길면 실패 기준 재설정). 잠든 동안 올라온 상품은 깨어난 뒤 알림(기존 로직). 관리 화면은 맥북 자신과 Tailscale(100.64.0.0/10)에서 온 접속만 허용(카페 와이파이 등 차단). Windows의 .env·keywords.txt·state.json을 옮겨 토픽·기억 유지, Windows 작업 해제로 중복 알림 방지. quickstart는 macOS 본문 + Windows 부록."

> 범위의 기준은 루트 `intent.md`(1단계)다. 001-keyword-alarm의 기능(조회·판정·번역·알림·키워드 관리)은 그대로이고,
> 이 명세는 **실행 환경이 바뀌면서 달라지는 동작**만 다룬다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 맥북이 깨어 있는 동안 알림 받기 (Priority: P1)

사용자는 맥북에 로그인해 쓰는 동안(덮개가 열려 있음) 따로 아무것도 실행하지 않아도 알림기가 돌고 있고,
새 상품 알림을 지금처럼 1~2분 안에 폰으로 받는다. 맥북을 한동안 손대지 않고 둬도(화면이 꺼지거나 잠겨도) 알림은 계속 온다.

**Why this priority**: 이전의 핵심. 이것만 되면 Windows PC 없이 알림기를 쓸 수 있다.

**Independent Test**: 맥북을 재시동하고 로그인만 한 뒤, 아무것도 실행하지 않고 폰 알림이 오는지 본다.
맥북을 10분 이상 손대지 않고 둔 뒤에도 알림이 오는지 본다.

**Acceptance Scenarios**:

1. **Given** 알림기가 설치된 맥북, **When** 사용자가 로그인함, **Then** 별도 조작 없이 알림기가 시작된다.
2. **Given** 알림기가 실행 중, **When** 알림기가 비정상 종료됨, **Then** 자동으로 다시 시작된다.
3. **Given** 덮개가 열려 있고 사용자가 아무 조작도 하지 않음, **When** 평소라면 맥북이 저절로 잠들 시간이 지남,
   **Then** 맥북이 잠들지 않고 알림이 계속 온다 (화면은 꺼지거나 잠겨도 된다).
4. **Given** 알림기가 실행 중, **When** 사용자가 덮개를 닫거나 메뉴에서 잠자기를 누름, **Then** 맥북은 평소처럼 잠든다.

---

### User Story 2 - 잠자기 후 깨어날 때 자연스럽게 이어지기 (Priority: P1)

사용자가 맥북을 덮고 이동한 뒤 다시 열면, 그 사이 올라온 상품이 알림으로 오고, 고장이 아닌데 "조회 실패 중" 경고가 오지는 않는다.

**Why this priority**: 들고 다니는 맥북은 하루에도 여러 번 잠들고 깬다. 깰 때마다 잘못된 경고가 오면 경고 자체를 믿을 수 없게 된다.

**Independent Test**: 키워드가 등록된 상태로 맥북을 30분 이상 덮어 두었다가 연다. 경고 없이, 그 사이 올라온 상품 알림이 온다.

**Acceptance Scenarios**:

1. **Given** 맥북이 10분 넘게 잠들어 있었음, **When** 깨어난 직후 네트워크가 아직 연결되지 않아 조회가 실패함,
   **Then** "조회 실패 중" 경고를 보내지 않는다.
2. **Given** 맥북이 깨어난 뒤에도 조회가 계속 실패함, **When** 깨어난 시점부터 10분이 지남, **Then** 경고를 한 번 보낸다.
3. **Given** 맥북이 잠든 동안 키워드에 맞는 새 상품이 올라옴, **When** 깨어난 뒤 첫 조회가 성공함,
   **Then** 그 상품들을 알린다 (6건 이상이면 기존 규칙대로 5건 + "외 N건").

---

### User Story 3 - 밖에서도 관리 화면은 나만 열기 (Priority: P2)

사용자는 카페·학교 와이파이에 맥북을 연결한 상태에서도 폰(Tailscale)으로 관리 화면을 열어 키워드를 바꿀 수 있고,
같은 와이파이에 있는 다른 사람은 관리 화면을 열 수 없다.

**Why this priority**: 관리 화면에는 로그인이 없다. 집 PC에서는 집 와이파이만 감수하면 됐지만, 맥북은 공용 와이파이에 붙는다.

**Independent Test**: 같은 와이파이의 다른 기기(Tailscale 꺼짐)에서 맥북의 와이파이 주소로 관리 화면을 열어 거절되는지,
폰(Tailscale 켬)에서는 열리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 폰이 Tailscale에 연결됨, **When** 맥북의 Tailscale 주소로 관리 화면을 엶, **Then** 정상적으로 열리고 키워드를 바꿀 수 있다.
2. **Given** 같은 와이파이의 다른 기기가 Tailscale을 쓰지 않음, **When** 맥북의 와이파이 주소로 관리 화면에 접속,
   **Then** 거절된다 (목록 조회·추가·삭제 모두).
3. **Given** 맥북 자신, **When** 브라우저로 `localhost` 관리 화면을 엶, **Then** 정상적으로 열린다.

---

### User Story 4 - Windows에서 기억 그대로 옮겨오기 (Priority: P2)

사용자는 Windows에서 쓰던 키워드·알림 토픽·이미 본 상품 기억을 맥북으로 옮겨, 폰 설정을 바꾸지 않고 그대로 이어서 쓴다.
옮긴 뒤 같은 상품 알림이 두 번 오지 않는다.

**Why this priority**: 한 번만 하는 이전 작업이지만, 빠뜨리면 알림 중복(두 기기 동시 실행)이나 기존 상품 알림 폭탄이 생긴다.

**Independent Test**: 옮긴 뒤 폰 ntfy 구독을 바꾸지 않고 알림이 오는지, 같은 상품 알림이 한 번만 오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Windows의 설정·키워드·기억 파일을 맥북 실행 폴더로 복사함, **When** 맥북 알림기가 시작됨,
   **Then** 같은 키워드 목록이 보이고, 기존 폰 구독으로 알림이 온다.
2. **Given** 이전을 마침, **When** 이후 새 상품이 올라옴, **Then** 알림은 한 번만 온다 (Windows 알림기는 꺼져 있음).

### Edge Cases

- **덮개를 닫지 않고 잠자기를 누름**: 덮개를 닫은 것과 같다. 잠든 동안 알림 없음. 자리를 비울 때는 화면 잠금을 쓰면 계속 동작한다.
- **배터리로 덮개를 연 채 방치**: 저절로 잠들지 않으므로 배터리가 평소보다 빨리 닳는다 (화면은 꺼짐). 감수.
- **아주 오래 잠듦**(예: 하루): 그 사이 갱신이 120건을 넘은 키워드는 놓친 상품이 있을 수 있다 → 기존 포화 경고 로그.
- **깨어났는데 네트워크가 몇 분째 없음**(비행기 모드 등): 깨어난 시점부터 10분 동안 계속 실패하면 경고 시도.
  네트워크가 없어 보낼 수 없으면 연결된 첫 시점에 보낸다 (기존 규칙).
- **잠든 시간이 아니라 조회가 오래 걸려 주기가 늦어짐**(예: 번역·알림 서버 지연): 잠자기로 오인할 만큼 길지 않으면 실패 기준을 재설정하지 않는다.
- **로그아웃 상태**: 알림기는 사용자가 로그인해 있을 때만 돈다.
- **집 와이파이에서 폰이 Tailscale을 끈 채 접속**: 거절된다. 폰은 항상 Tailscale 주소로 접속한다.
- **Windows 알림기를 끄지 않고 맥북도 켬**: 같은 토픽으로 알림이 두 번씩 온다 → 이전 절차에서 Windows 작업 해제를 필수 단계로 둔다.

## Requirements *(mandatory)*

### Functional Requirements

**상시 실행 (US1)**

- **FR-101**: 알림기는 사용자가 맥북에 로그인하면 자동으로 시작되어야 하고, 비정상 종료되면 자동으로 다시 시작되어야 한다(MUST).
  (001의 FR-020 "로그인하지 않아도 부팅 시 시작"을 대체)
- **FR-102**: 알림기가 실행 중인 동안 맥북은 사용 안 함 상태로 저절로 잠들면 안 된다(MUST NOT). 화면 꺼짐·화면 잠금은 허용한다.
- **FR-103**: 덮개를 닫거나 사용자가 직접 잠자기를 선택하면 맥북은 평소처럼 잠들어야 한다(MUST). 알림기가 이를 막으면 안 된다.
- **FR-104**: 알림기는 실행 중 창이나 Dock 아이콘을 띄우지 않아야 한다(MUST). (001의 FR-021 대응)
- **FR-105**: 알림기 실행에 쓰는 코드·설정·기억 파일은 개발용 작업 폴더와 분리된 실행 전용 폴더에 둔다(MUST).

**잠자기 대응 (US2)**

- **FR-106**: 조회 주기 사이 실제 경과 시간이 정상 주기보다 비정상적으로 길면(3분 이상) 맥북이 잠들었다 깨어난 것으로 보고,
  연속 실패 판정의 기준 시각을 그 시점으로 재설정해야 한다(MUST). 이때 기록을 로그에 남긴다.
- **FR-107**: 재설정 후에는 기존 규칙(10분 연속 실패 시 경고 1회, 성공 시 초기화)을 그대로 따른다(MUST).
- **FR-108**: 잠든 동안 올라온 상품은 깨어난 뒤 조회에서 기존 판정·묶음 규칙으로 알린다(MUST). (기존 동작 유지)

**접근 제한 (US3)**

- **FR-109**: 관리 화면과 키워드 API는 맥북 자신(루프백)과 Tailscale 사설망(100.64.0.0/10)에서 온 요청만 받아야 하고,
  그 외 주소에서 온 요청은 모두 거절해야 한다(MUST). 001의 Host 검사는 유지한다.

**이전 (US4)**

- **FR-110**: 설치 안내는 Windows의 알림 토픽 설정·키워드 목록·본 상품 기억을 맥북 실행 폴더로 옮기는 단계와,
  Windows 자동 실행을 해제하는 단계를 포함해야 한다(MUST).
- **FR-111**: 설치 안내는 macOS 절차를 본문으로 하고, Windows 절차는 부록으로 남긴다(MUST).

### Key Entities

- **실행 폴더**: 알림기 코드(배포 브랜치 고정)와 설정·키워드·기억·로그가 있는 맥북의 폴더. 개발 폴더와 별개.
- **고장 감지 상태**(001에서 확장): 마지막 조회 성공 시각, 경고 발송 여부, **마지막 주기 시작 시각**(잠자기 감지용).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-101**: 맥북을 재시동하고 로그인만 하면 **5분 안에** 알림기가 동작한다 (폰에서 관리 화면이 열림).
- **SC-102**: 덮개를 연 채 **30분 이상** 손대지 않아도 알림이 계속 온다.
- **SC-103**: 1주일 동안 맥북을 평소처럼 덮고 열어도 **고장이 아닌데 "조회 실패 중" 경고가 오는 일이 0건**이다.
- **SC-104**: 맥북을 열고 나서 **2분 안에** 잠든 동안 올라온 상품 알림이 온다 (최근 120건 범위).
- **SC-105**: 같은 와이파이의 다른 기기에서 관리 화면 접근 시도가 **100% 거절**된다.
- **SC-106**: 이전 후 1주일 동안 **같은 상품 알림이 두 번 오는 일이 0건**이다.
- **SC-107**: 추가 비용 0원.

## Assumptions

- 사용자는 맥북을 들고 다니며, 덮개를 닫은 동안의 알림 공백을 감수한다 (intent).
- 맥북에는 Python 3과 Tailscale이 설치되어 있고, 폰도 같은 Tailscale 계정에 연결되어 있다.
- 폰은 집에서도 Tailscale을 켠 채 관리 화면에 접속한다. 집 와이파이에서 Tailscale 없이 직접 접속하는 방법은 없어진다.
- 알림 토픽은 Windows에서 쓰던 것을 그대로 옮겨 폰 구독을 유지한다.
- 이전 후 Windows 알림기는 해제한다. 두 기기 동시 운영은 범위 밖 (intent "하지 않는 것").
- "비정상적으로 긴 주기 간격"은 3분으로 둔다: 정상 주기(1분) + 최악 지연(번역 생략 후 알림 지연)보다 충분히 길고, 잠자기 대부분을 잡는다.
